## 7. Project-Specific README Content

### AI Governance & Assessment Platform

**Problem:** Organizations need a consistent way to assess proposed AI use cases before deployment. Asking a language model to label an application as high risk does not provide a repeatable, auditable, or defensible decision process.

**Solution:** The platform collects structured use-case information, evaluates defined governance dimensions using weighted rules, records findings and recommendations, and links conclusions to categorized public sources. It distinguishes laws and regulations, regulatory guidance, industry standards, research, vendor information, and general web content.

**Key features:**

- Structured AI use-case intake
- Repeatable weighted risk scoring
- Privacy, fairness, oversight, explainability, security, impact and monitoring assessment
- Source classification and citation metadata
- Findings, controls and recommended actions
- Assessment history and methodology transparency
- Deterministic demo mode when an LLM provider is unavailable

### AI Fitness Coach

**Problem:** Generic workout plans do not account for differences in goals, fitness level, schedule, available equipment, and constraints.

**Solution:** The application gathers user preferences and generates structured workout recommendations through modular frontend and backend services.

**Key features:** personalized plans, user profiles, progress tracking, secured APIs, containerized services, responsive dashboard, input validation and error handling.

### Dokmark

**Problem:** Users often lose useful resources across browser bookmarks, messages, and notes.

**Solution:** Dokmark provides a centralized place to save, organize, search, and manage bookmarks securely.

**Key features:** OAuth login, bookmark CRUD, collections or tags, search and filtering, responsive interface, validation, protected routes and CI/CD deployment.

9. Security Cleanup

Before making any repository public:

Remove .env files, API keys, passwords, database connection strings and tokens.

Search Git history, not only the current files, for exposed secrets.

Rotate every credential that has ever been committed.

Add .env, build output, logs, uploads and local database files to .gitignore.

Provide .env.example containing variable names only.

Do not publish proprietary AIEnsured code, screenshots, test data or internal documentation.
